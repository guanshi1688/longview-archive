## 一｜骨架：文明结构算法

**正式中文：** `chinese/文明结构/`（资料库镜像）  
**正式英文：** `English/structural-algorithm/`（资料库镜像）  
**本地 Git 原文位置：** `../index/structural-algorithm/chinese/` 与 `../index/structural-algorithm/english/`，以本地实际仓库为准；前述资料库名称是便于上传的映射，不是 Git 目录改名指令。

### 核心研究对象

1. 生存要求下一轮生活与生产所需的物质条件继续形成。
2. 物质生产需要组织；国家、市场、企业、金融等是不同形式的组织能力，而不是预设的理论起点。
3. 环境、人口、技术、交通与外部关系带来不同、反复出现的压力；若一种组织办法长期处理这些压力、保存能力并在失效后重新被调用，便可能形成主导组织形式。
4. 研究宏观的长期方向，不把任何国家、社会或个人写成不可改变的类型，也不宣称历史结果可由单一公式预测。

### 两种重要组织方向

| 组织方向 | 首先保存的能力 | 关键问题 |
|---|---|---|
| 生产型组织／Production-bearing organisation | 实际形成、维护、恢复生产能力 | **下一轮还能不能造出来？** |
| 接口型组织／Interface-oriented organisation | 连接、获取、调用已有生产能力的关系 | **下一轮还能不能调用？** |

两种方向不是两个互斥物种。生产型组织使用市场、信用、标准和结算；接口型组织也经营工厂、运输、技术、安全和基础设施。检验点是能力冲突、主要责任和失效重建时，哪一种关系持续组织其他能力。

**Interface／接口：** 指准入、连接、验证、定价、融资、结算、退出、重连等系统位置与机制。不能把它简单当作独立于生产的物质来源、文明灵魂或不可改变的本体标签。

### 最新骨架的正文顺序

```text

共同 00｜生产力的组织形式与文明投影

```

中文和英文各有上述 26 份**独立正文**（规则、术语、00、两条 01—11、12），不把构建脚本或内部合订本计为额外正文。两条历史路线独立展开；共同 00 与 12 只在每种语言中各计一次。

**公开边界：** 骨架属于未公开正式母版；部分术语和局部机制可在公开 Framework、专题和投稿中出现，但不要因导航便利或 Corpus 生成而直接公开完整母链。

## 二｜说明书：组织经济学

**中文：** `chinese/组织经济学/`  
**英文：** `English/organisation_economics/`  
**Git 网站路径：** `docs/essays/chinese/organisation_economics/`、`docs/essays/english/organisation_economics/`。

**定位：** 《文明结构算法》提供组织形式的历史生成骨架；《组织经济学》提供同一个物质生产循环的运行说明。它不再分“中国经济学”和“西方经济学”两卷，也不声称经济学说明书比骨架更底层。

**一句话：** 生产力不只要造得出，还要调得到、卖得出、用得起，并在失败后能重新开始。

## 三｜深入展开：其他文章

第三类不是与“骨架／说明书”并列争夺定义权的上位理论。它包括历史案例、现实观察、机制压力测试、制度比较、专题综合和面向特定读者的外部稿件。

| 内容 | 工作位置 |
|---|---|
| `Reality｜现实世界` | 将组织关系和经济运行机制用于当代可观察压力 |
| `Future Path｜未来之路` | 研究生产富余、承接与可能的下一轮社会再生产安排 |
| 六大英文系列 | 按边疆扩张、生产架构、发展边界、价值捕获、中国生产负担、技术放大等问题域分组展开 |
| 中文札记 | 用具体历史与生产现象切入独立局部因果链 |
| 工业化的人力架构及其他专题 | 对特定机制进行跨历史、跨制度或跨人群的较深展开 |
| 独立短文、EHS、SSRN、Rome、Phenomenal World、Reddit、Medium、Substack 等 | 特定读者和出版要求下的独立论证与对外输出 |

归档只表明理论位置，不宣告每篇文章的经验结论已经得到验证。历史观察、反例和新证据应当能够支持、限定、修订或推翻相应的因果箭头。

**不机械强制“所有文章都必须从骨架第一节重讲一遍”。** 具体文章宜从读者看到的现象起步，给出所需的最小机制及证据，隐藏无关上游和下游，而不是把完整母版搬到外部平台。

## 五｜新稿归档与检验规则

依次判断：

1. **它是否改变生产力组织形态的形成、主导、失效或恢复机制？** 若构成稳定且经过压力测试的基础变动，候选进入新版《文明结构算法》；此前先放工作稿。
2. **它是否补足运行循环中的经济机制？** 若属于系统性的能力组织、接口、订单、消费、责任、失败或再生产机制，候选进入《组织经济学》；此前先放工作稿。
3. **它是否是在某个历史、地区、制度或当代现象上展开一个机制？** 放历史／现实／专题／系列／独立文章；无需制造第三套母理论。
4. **它是否只是同一论证面向另一平台的包装？** 归入对外投稿或平台稿，关联上游源稿，不把平台版本反向当成理论母版。
5. **它是否是过时体系、废弃章节或中间推演？** 放旧材料／历史记录，不参与当前默认检索。

### 经验检验的最小要求

- 先明确待解释的现象、发生时间和比较单位。
- 说清组织机制、责任所在、失效边界以及下一轮能力的保存方式。
- 区分“在历史上存在过”与“反复取得组织上的主导位置”。
- 不以文明标签代替对多种可能解释的检验。
- 不把“可解释一种结果”写成“必然产生该结果”，也不从制度差异直接推算转型时间。
- 具体历史和现代事实须回到原始或可靠研究材料单独验证。
